# 山海（ShanHai）创作工作台最小实现方案

**日期：** 2026-08-12
**状态：** Reviewed（MVP，可进入实施）
**范围：** 复用现有“新建创作项目”和“打开创作项目”，覆盖新书、续写和当前章节审稿

## 1. 品牌与命名

产品对外名称统一为 **山海（ShanHai）**。`Novel Studio` 是早期产品叫法。

本方案只约束新的用户可见文案和功能命名，不批量修改 `@novel-studio/*` 包名、IPC 标识、已有项目格式和历史文档；技术标识迁移不属于本次 MVP。

## 2. 结论

顶部文件菜单不新增“导入已有小说”。继续保留两个入口：

1. **新建创作项目**：在用户选择的父目录下创建一个新的山海项目文件夹。
2. **打开创作项目**：选择一个小说文件夹；如果它已经是山海项目就直接打开，如果只是普通正文文件夹就询问是否在原地初始化。

新书、续写、审稿也不做成项目类型或持久化工作模式。项目打开后，只根据当前项目是否有章节，在右侧 Agent 会话中提供不同的开场动作。

## 3. “打开创作项目”当前行为

现有“打开创作项目”是可用功能，但只能打开已经初始化过的创作项目：

- 用户选择一个目录。
- Main 将该目录交给创作项目激活流程。
- Repository 读取并校验根目录下的 `project.json` 和 `settings.json`。
- 校验成功后加载章节、Story Bible、文件树和 Agent 工作区。

因此，它现在能重新打开由应用创建的项目，但不能打开一个只包含二十篇 `.txt/.md` 正文的普通文件夹；这种目录目前会被判定为“不是创作项目”。

MVP 不改变菜单名称，只扩展“打开创作项目”选择目录后的分支判断。

## 4. 打开目录后的最小分支

### 4.1 已有山海项目

目录中存在有效的 `project.json` 和 `settings.json`：沿用现有打开流程，不迁移文件、不重新初始化。

### 4.2 普通小说文件夹

目录中不存在 `project.json`，但根目录包含受支持的 `.txt` 或 `.md` 文件：

1. 只读扫描根目录正文候选文件，按自然文件名顺序排列。
2. 显示预览确认界面，列出候选文件、章节顺序和标题；允许用户取消勾选笔记、`README.md` 或其他不应作为章节的文件，并调整顺序。
3. 提示：将直接在当前文件夹中建立山海项目，以后正式正文统一由 `chapters/` 管理；确认前不写入或移动任何文件。
4. 用户确认后，在当前目录执行原地初始化和章节转换；只处理确认勾选的文件，未勾选文件保持不变。
5. 初始化成功后，再调用现有项目激活流程并打开最后一个已导入章节。

至少需要确认一份章节文件；如果用户全部取消勾选或取消确认，则直接结束流程，不创建空项目，也不修改原目录。

这是同一个“打开创作项目”菜单下的两阶段内部流程：先做只读预检和预览，用户确认后才初始化，完成后再激活项目；不把预览结果直接伪装成现有工作区激活结果。

这不是新的“导入”功能入口，而是“打开创作项目”首次接入普通小说文件夹时的初始化步骤。

### 4.3 可疑或损坏目录

以下情况停止处理，不把目录当成普通小说重新初始化：

- 存在 `project.json`，但内容损坏或 schema 校验失败。
- 存在 `settings.json`、`.novel-studio` 或其他受管项目目录，但缺少完整项目元数据。
- 存在受管的 `chapters/` 或 Story Bible 目录，但缺少完整项目元数据。
- 没有可识别的正文文件。
- 文件编码、路径或大小不受支持。

界面只显示明确的修复提示，不覆盖任何现有文件。

## 5. 正文唯一来源

项目初始化后，正式正文只能存在于：

```text
项目根目录/
├─ chapters/                    正式章节
├─ characters/
├─ world/
├─ outline/
├─ timeline/
├─ .novel-studio/import-backup/  原稿备份，不参与写作上下文
├─ project.json
└─ settings.json
```

转换规则保持最小：

- MVP 只识别所选目录根层级的 `.txt`、`.md` 文件，不递归猜测卷目录。
- 每个确认的源文件转换成标准 `chapters/<chapterId>.md`，补充章节 frontmatter；`chapterId` 由现有 Application/Repository 生成合法且唯一的 `ch_...` ID，不要求跨次重导入保持相同。
- 导入清单记录源文件、预览时的大小/校验和、目标章节，以及本次创建/移动的路径映射；正式写入和移动前重新校验源文件未被外部修改。
- 标题默认来自文件名，顺序使用自然排序，并允许用户在确认前调整。
- 所有目标章节写入并校验成功后，源文件才移动到 `.novel-studio/import-backup/<时间戳>/`；未勾选源文件不移动。
- 备份目录必须从章节列表、项目搜索、文件树和 Agent 默认上下文中排除。
- 任一步骤失败时，按导入清单删除本次生成的章节、项目文件和目录，恢复已经移动到备份目录的源文件，并保持导入前已存在的文件不变；永远不删除用户选择的根目录，也不留下两套正式正文。

后续新增章节继续写入同一个 `chapters/`，不会写到项目父目录或原稿位置。

## 6. 三种使用场景的最小闭环

不增加 `CreativeWorkMode`，不保存“新书 / 续写 / 审稿”状态。右侧 Agent 只提供预设开场动作；点击动作只把请求填入现有 Agent Composer，用户可以编辑后再发送，并继续经过现有发送预览、上下文预算、权限和审批流程。

### 6.1 新书

条件：项目有 0 章。

右侧 Agent 显示 **开始构思**：

```text
请引导我构思这本小说。每次只问一两个关键问题，优先了解作品类型、
目标、核心冲突、主角和世界背景。信息足够后先总结，经过我确认，
再提议把明确内容写入大纲、人物或世界观资料；不要自行补全未确认设定。
```

实现直接复用现有会话 Agent、Story Bible 创建/修改提案和 Change Set 审批。无需新增引导状态机、问卷或新的数据表。

### 6.2 续写

条件：项目已有章节。

右侧 Agent 显示两个动作：

**继续写作**

```text
请读取当前章节、前一章和必要的项目上下文，先与我确认下一章方向，
再创建或续写章节。不要自动修改故事资料。
```

**梳理已有内容**

```text
请先列出并分批阅读现有章节，整理人物、世界设定、主线和未回收伏笔。
先向我展示摘要和待确认项；只有我明确确认后，才提议写入故事资料。
```

“梳理已有内容”是可选会话请求，不在打开项目时自动运行，也不新增全书批处理引擎。普通续写可以直接开始；Agent 使用现有章节读取、搜索和 Story Bible 工具按需收集上下文。

### 6.3 审稿

条件：当前打开了一个章节。

右侧 Agent 显示 **审稿当前章**：

```text
请只读审阅当前章节，指出结构、动机、节奏、设定一致性和语言问题，
并给出具体修改建议。不要修改正文或故事资料，除非我随后明确要求并确认变更。
```

该动作同时把现有 Agent Run draft 预设为 `planning`（只读）模式；如果首版暂时不能自动切换，界面必须明确要求用户先选择计划/只读模式。只靠 Prompt 不视为只读保证。审稿结果进入现有会话历史，不进入 Story Bible。用户随后要求修改正文时，切换到正常执行模式，并继续使用现有章节 Change Set 和差异审批。

MVP 不做全书一键审稿。用户可以逐章审稿，或在会话中明确要求 Agent 扩大读取范围。

## 7. 最小代码改动范围

### 7.1 扩展现有打开流程

- 在现有 `chooseOpenCreativeDirectory` 和 `openCreativeProject` 链路中增加目录分类。
- 有效项目继续走现有 `openProject()`。
- 普通正文文件夹先通过同一打开命令下的内部预览/确认流程返回只读初始化预览；预览不是 `WorkspaceActivationDto`，用户确认后才执行初始化。有效项目的现有 `openCreativeProject` 激活返回合同保持不变。
- 原地初始化使用独立的初始化事务，不能复用 `createProjectInParent` 针对新建子目录的递归清理逻辑。事务记录本次创建的目录、项目文件、章节文件和已移动源文件；失败时只撤销这些记录，永远不删除用户选择的根目录或导入前已存在的文件。
- 用户确认后，在该目录创建项目基础文件和受管目录，并转换确认勾选的章节。
- 转换完成后调用现有工作区激活流程。

不新增顶部菜单、文件选择器或独立“导入项目”导航。

### 7.2 增加 Agent 开场动作

- 项目 0 章时显示“开始构思”。
- 项目有章节时显示“继续写作”和“梳理已有内容”。
- 当前有活动章节时同时显示“审稿当前章”。
- 点击动作只把固定请求填入现有 Agent Composer，不自动发送，不改变项目 schema、Agent 配置或会话类型；发送仍走现有预览、预算、权限和审批流程。
- “审稿当前章”把 Agent Run draft 预设为 `planning`（只读）模式；无法自动预设时必须在界面要求用户选择该模式。

## 8. MVP 明确不做

- 不新增“导入已有小说”菜单或按钮。
- 不新增三种项目类型、工作台或持久化工作模式。
- 不新增专用构思 Agent、续写 Agent 或审稿 Agent。
- 不在打开项目时自动分析全部章节。
- 不自动把 AI 摘要写入 Story Bible。
- 不做全书一键审稿、全书分析进度管理或语义索引。
- 不支持递归识别复杂卷目录、Word、PDF 或其他格式。
- 不批量重命名已有内部 `novel-studio` 技术标识。

## 9. 验收标准

### 打开已有项目

- 顶部“打开创作项目”仍能正常打开现有有效项目。
- 损坏项目不会被误判为普通目录并覆盖。

### 首次打开普通小说文件夹

- 同一个“打开创作项目”入口能够识别根目录的 `.txt/.md` 正文。
- 用户确认前不写入或移动任何文件。
- 用户能看到并确认章节候选、顺序和标题；未勾选文件不被修改或移动。
- 初始化后，所选文件夹本身是项目根目录，正式章节全部位于 `chapters/`。
- 原稿保存在隐藏备份中，且不进入章节列表、搜索或 Agent 默认上下文。
- 预览后源文件发生变化时，初始化会停止且不写入或移动文件。
- 导入失败时，原稿仍完整可用，已生成章节和已移动文件按清单撤销/恢复。
- 后续新章节继续写入同一个 `chapters/`。

### Agent 开场

- 空项目显示“开始构思”，Agent 会逐步询问并在写资料前请求确认。
- 有章节项目可以直接“继续写作”，不会强制分析历史章节。
- “梳理已有内容”只生成待确认摘要或提案，不自动写入故事资料。
- “审稿当前章”使用现有 `planning`/只读模式，修改正文仍需切换正常执行模式并经过差异预览和确认。

### 通用

- 不新增项目 schema 或工作模式状态。
- 所有正式写入继续经过现有校验、审批、事务和恢复边界。
- 相关 Repository、Application、IPC、Renderer 和 UI 定向测试通过。

## 10. 推荐实施顺序

1. 先扩展“打开创作项目”的目录识别、确认、原地初始化和章节转换。
2. 再增加三个 Agent 开场动作。

两部分即可覆盖新书、续写和当前章节审稿，不需要另写一份实施文件，也不需要在 MVP 中建设全书分析系统。
